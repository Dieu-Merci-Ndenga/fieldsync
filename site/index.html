Features

Built for the places the network isn't.

Basements, plants, rural sites. FieldSync assumes failure and is designed so failure is never visible in your data.

Local-first writes

Every edit is saved to SQLite and queued before any network call. A crash or a dead zone never loses work.

Resumable sync queue

An ordered outbox retries automatically on reconnect, with idempotent operations so replays are harmless.

Field-level merge

Colleagues editing different fields merge automatically. Only real collisions need a human.

Explicit conflicts

Conflicting edits are parked, never applied silently. Choose to keep yours or theirs.

Photos that never block

Uploads run in their own queue. A rejected photo is parked with Retry or Remove.

Full change history

An append-only log records author, version and whether a change was auto-merged.

How it works

At-least-once delivery, exactly-once effect.

Exactly-once delivery is impossible over an unreliable network, so every operation carries a UUID and the server makes replays harmless.

Write locally

Each edit becomes an operation with a stable UUID, stored in the on-device outbox before anything touches the network.

Push in order

The server locks the record, merges inside a transaction, logs the change and remembers the operation id.

Merge or park

Disjoint fields merge. Identical values are accepted. Different values become a conflict for the user to decide.

Resume safely

Lost responses are fine: replaying an operation returns the original result instead of applying it twice.

Conflicts

Two people. One field. Your call.

When two users change the same field while offline, FieldSync shows both versions side by side instead of picking a winner.
